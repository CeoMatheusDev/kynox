## Build

```sh
zig version          # must print 0.17.0
zig build            # bootloader + kernel + native apps + EFI image
ls zig-out/bin       # kynox-boot.efi, kynox-kernel, kynox.img
```

Recorded result at draft time (2026-10-31, Zig 0.17.0): `zig build` green,
13/13 steps at the time of the record; artifacts `kynox-boot.efi` (181,760 B), `kynox-kernel` (65.7 MB,
debug), `kynox.img` (128 MiB FAT ESP, 32,731 clusters).

## Run

```sh
zig build qemu                       # interactive boot in QEMU
```

or, manually:

```sh
qemu-system-x86_64 -machine q35 -m 512M \
  -drive if=pflash,format=raw,readonly=on,file=$OVMF_CODE \
  -drive if=pflash,format=raw,file=$OVMF_VARS \
  -drive format=raw,file=zig-out/bin/kynox.img \
  -serial stdio
```

The exact flags used by the repository are in `scripts/qemu-run.sh`; follow the
script rather than the sketch above if they differ.

## Known issues

1. ~~Version identifiers disagree~~ — fixed: `version.zig` is the only source
   and `version-tests` fails on divergence. Audit A-01 closed.
2. The LAPIC base now comes from the MADT with validation and a logged
   fallback, and the I/O APIC redirection entries for the PIT and the keyboard
   are programmed — **masked**. Delivery still comes from the 8259; the
   `-Dioapic-delivery=true` switch has never been booted, so no interrupt has
   been observed through the I/O APIC and the path has never run in a VM.
   Audit A-03 partially closed.
3. ~~The ABI revision is claimed only by the SDK~~ — fixed: revision 1 lives in
   `shared/syscall_abi.zig`, aliased by kernel and SDK, checked by
   `abi-conformance-tests`. The ABI is still unstable and never ran in a VM.
4. SMP: the CPU table is built from the MADT, but the trampoline is never
   published below 1 MiB, so `startAps()` refuses to start any AP. No AP has
   ever run.
5. VirtIO Block completion is polling-based; no interrupt/MSI-X, no multi-queue.
6. Persistence is bounded to the KNV commit/recover probe; no journal, no
   power-loss guarantee.
7. A CI workflow is defined but has never run; no QEMU result is recorded in
   the repository.
8. No Linux or Windows compatibility runtime.
